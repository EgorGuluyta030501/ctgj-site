# CTGJ — сайт и админ-панель заявок

## Запуск

Нужен Node.js 22.13 или новее. Устанавливать пакеты не нужно: зависимостей нет, база данных — встроенный SQLite.

```bash
node server.js
```

- Сайт: http://localhost:3000
- Админ-панель: http://localhost:3000/admin/

При первом запуске в консоли появятся логин и пароль администратора. Чтобы задать их заранее:

```bash
ADMIN_LOGIN=admin ADMIN_PASSWORD=СвойПароль123 node server.js
```

Сменить пароль любому пользователю:

```bash
node server.js set-password admin НовыйПароль123
```

Заявки и пользователи хранятся в `data/ctgj.db`. Этот файл нужно включить в резервное копирование.

## Админ-панель

- **Администратор** видит все заявки, назначает менеджеров (прямо в таблице или в карточке заявки), меняет статусы, удаляет заявки, выгружает их в CSV для Excel, добавляет и отключает менеджеров.
- **Менеджер** видит только назначенные ему заявки, меняет их статус и добавляет заметки.
- Статусы: Новая → Назначена → В работе → Завершена / Отказ.
- У каждой заявки хранится история: кто и когда её назначил, сменил статус или оставил заметку.
- Список обновляется каждые 30 секунд. Число новых заявок показывается во вкладке браузера.

### Уведомления в Telegram (по желанию)

1. Создайте бота через @BotFather и получите токен.
2. Добавьте бота в нужный чат и узнайте `chat_id`.
3. Запустите сервер так:

```bash
TG_BOT_TOKEN=123:ABC TG_CHAT_ID=-100123456 node server.js
```

## Что заменить перед запуском

- **Контакты** в `public/index.html` (секция `#contacts`): телефон, email, ссылки на WeChat, WhatsApp и Telegram.
- **Адрес** в `public/js/i18n.js`, ключ `contacts.addressValue`, на всех трёх языках.
- **Проекты** в `public/index.html` (секция `#projects`): сейчас там примеры направлений, их нужно заменить на реальные проекты.
- **Описания услуг** `svc.N.d` в `public/js/i18n.js`: их стоит согласовать с заказчиком.
- **Английские и китайские тексты** в `public/js/i18n.js`: их стоит показать носителю языка.

## Фоновое видео на главной

Файлы лежат в `public/video/`:

- `hero.mp4` — для компьютеров, 1600px, около 3,4 МБ;
- `hero-mobile.mp4` — для телефонов, 960px, около 1,4 МБ;
- `hero-poster.jpg` — первый кадр. Он показывается, пока видео грузится, а также при включённой экономии трафика или «уменьшении движения» в системе.

Чтобы заменить видео, сожмите новый ролик без звука командой ffmpeg:

```bash
ffmpeg -i новое.mp4 -an -vf scale=1600:-2 -c:v libx264 -preset slow -crf 30 -pix_fmt yuv420p -movflags +faststart public/video/hero.mp4
ffmpeg -i новое.mp4 -an -vf scale=960:-2 -c:v libx264 -preset slow -crf 30 -profile:v main -pix_fmt yuv420p -movflags +faststart public/video/hero-mobile.mp4
ffmpeg -i новое.mp4 -vf scale=960:-2 -frames:v 1 -q:v 5 public/video/hero-poster.jpg
```

Насколько затемнено видео, задаёт класс `.hero__shade` в `public/css/style.css`.

## Структура

```
server.js              сервер: статика, API заявок, авторизация
public/
  index.html           сайт
  css/style.css        стили
  js/dragon.js         дракон и ночная сцена на canvas (прелоадер и первый экран)
  js/i18n.js           тексты RU / EN / 中文
  js/main.js           языки, анимации, фонари, конверт с формой
  img/                 логотип, силуэт пагод, иконка
  admin/               админ-панель
data/ctgj.db           база данных (создаётся автоматически)
```

Чтобы пропустить заставку при правках, откройте `/?intro=0`. Язык можно задать ссылкой: `/?lang=en` или `/?lang=zh`.

## Демо на GitHub Pages

При каждом push в `main` workflow `.github/workflows/pages.yml` публикует статичную копию папки `public/` на GitHub Pages. Админ-панель в эту копию не попадает.

На адресе `*.github.io` сайт работает в демо-режиме, потому что сервера там нет. Формы показывают полную анимацию отправки, но заявки никуда не уходят и в админку не попадают. Чтобы заявки действительно приходили, сайт нужно запустить через `node server.js` на хостинге (см. «Публикация»).

## Публикация

Подойдёт любой VPS с Node.js. Запустите `node server.js` через pm2 или systemd, а перед ним поставьте nginx с HTTPS:

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

Сервер нужно держать за прокси: он берёт IP клиента из `X-Forwarded-For` для защиты от спама.
